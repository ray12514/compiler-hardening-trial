# 03 — HDF5 2.1.0 with GCC 12.5.0

**Normal route:** follow the [README](README.md), then run `"$TRIAL_ROOT/runner/trial" build hdf5`. The driver runs the applicable blocks below in child shells, including prerequisites. These numbered sections are recipe references; do not paste all of them after using the driver.

Prerequisites: [00](00-gcc-bootstrap.md) and [01](01-common.md). Run shell blocks in order in Bash. Initial scope: shared serial C library and high-level library, tools/tests enabled, compression disabled. This measures HDF5 without changing a compression dependency. C++/Fortran and MPI extensions are separate sections below.

## 1. Build variants

`profile_flags "$p"` in [01](01-common.md) supplies the flags. Default listed `full` sets **`-fPIC -fstack-protector-strong -D_FORTIFY_SOURCE=2`** in `CFLAGS` and **`-Wl,-z,relro -Wl,-z,now`** in `SHARED_LDFLAGS`; the CMake arguments below pass them explicitly. The fixed benchmark caller uses **`-fPIE`** and **`-pie`**. This comparison covers the shared library and that caller; upstream HDF5 tools need their own executable PIE audit. See [07](07-consumer-pie.md) for the caller PIE comparison.

Start with `full reference`. Later build selected missing removal variants or the full `LIB_PROFILES` matrix. Use a fresh build/prefix for every variant. See [HDF5's source release](https://github.com/HDFGroup/hdf5/releases/tag/2.1.0) and [CMake build guidance](https://github.com/HDFGroup/hdf5/blob/develop/docs/INSTALL_CMake.md).

```bash
source "$TRIAL_ROOT/env.sh"
source "$TRIAL_ROOT/profiles.sh"
HDF5_SOURCE="$TRIAL_ROOT/src/hdf5-2.1.0"
HDF5_VARIANTS=(full reference)
for p in "${HDF5_VARIANTS[@]}"; do
    profile_flags "$p"
    build="$TRIAL_ROOT/build/hdf5-$p"
    prefix="$TRIAL_ROOT/install/hdf5/$p"
    test ! -e "$build"
    test ! -e "$prefix"
    mkdir -p "$TRIAL_ROOT/logs/hdf5/$p"
    declare -p CFLAGS SHARED_LDFLAGS > "$TRIAL_ROOT/logs/hdf5/$p/flags.txt"
    "$CMAKE" -S "$HDF5_SOURCE" -B "$build" -G 'Unix Makefiles' \
      -DCMAKE_C_COMPILER="$CC" -DCMAKE_BUILD_TYPE=Release \
      -DCMAKE_C_FLAGS="$CFLAGS" -DCMAKE_C_FLAGS_RELEASE='' \
      -DCMAKE_SHARED_LINKER_FLAGS="$SHARED_LDFLAGS" \
      -DCMAKE_EXE_LINKER_FLAGS="$EXE_LDFLAGS" \
      -DCMAKE_INSTALL_PREFIX="$prefix" -DCMAKE_INSTALL_LIBDIR=lib \
      -DCMAKE_EXPORT_COMPILE_COMMANDS=ON \
      -DBUILD_SHARED_LIBS=ON -DBUILD_STATIC_LIBS=OFF -DBUILD_TESTING=ON \
      -DHDF5_BUILD_TOOLS=ON -DHDF5_BUILD_HL_LIB=ON \
      -DHDF5_BUILD_CPP_LIB=OFF -DHDF5_BUILD_FORTRAN=OFF \
      -DHDF5_ENABLE_PARALLEL=OFF -DHDF5_ENABLE_THREADSAFE=OFF \
      -DHDF5_ENABLE_ZLIB_SUPPORT=OFF -DHDF5_ENABLE_SZIP_SUPPORT=OFF \
      -DHDF5_ENABLE_PLUGIN_SUPPORT=OFF -DHDF5_ENABLE_NONSTANDARD_FEATURE_FLOAT16=OFF \
      2>&1 | tee "$TRIAL_ROOT/logs/hdf5/$p/configure.log"
    "$CMAKE" --build "$build" --parallel "$JOBS" --verbose \
      2>&1 | tee "$TRIAL_ROOT/logs/hdf5/$p/build.log"
    "$CTEST" --test-dir "$build" --output-on-failure --parallel "$JOBS" \
      2>&1 | tee "$TRIAL_ROOT/logs/hdf5/$p/check.log"
    "$CMAKE" --install "$build" 2>&1 | tee "$TRIAL_ROOT/logs/hdf5/$p/install.log"
    cp "$build/CMakeCache.txt" "$build/compile_commands.json" "$TRIAL_ROOT/logs/hdf5/$p/"
    test -f "$prefix/lib/libhdf5.so"
    readelf -lW "$prefix/lib/libhdf5.so" > "$TRIAL_ROOT/logs/hdf5/$p/elf.txt"
    readelf -dW "$prefix/lib/libhdf5.so" >> "$TRIAL_ROOT/logs/hdf5/$p/elf.txt"
done
```

Review CMake's unused-variable warnings and the cache: a named option must actually exist in this release and have the intended value. The explicit Float16 option avoids making GCC's experimental floating-point support part of this I/O trial. Do not accept a configure fallback to another compiler or an unexpected compression provider. Stop on a correctness failure before timing.

## 2. Create the fixed serial I/O caller

The caller writes deterministic doubles, closes the file, reopens and reads it, then verifies every value. It measures write/create/close and read/open/close separately. Contiguous and chunked storage use the same logical data. An optional dataset count supports many small datasets in the same file, with creation and lookup included in the timed phases. No compression, MPI, or plugins are involved. Buffer allocation/initialization and correctness checking are outside the timed phases.

Use a dedicated trial filename: the caller truncates and removes that file on each invocation. A read immediately following a write is a **warm-cache read**, not a cold-storage bandwidth test. `durable=1` includes a POSIX `fsync` after HDF5 closes the file; report that setting. Filesystem durability still depends on the storage implementation.

```bash
cat > "$TRIAL_ROOT/bench/hdf5_bench.c" <<'C'
#define _POSIX_C_SOURCE 200809L
#include <hdf5.h>
#include <fcntl.h>
#include <math.h>
#include <stdio.h>
#include <stdlib.h>
#include <time.h>
#include <unistd.h>
#define CHECK(x) do { if ((x)<0) { fprintf(stderr,"HDF5 failure: %s\n",#x); exit(1); } } while(0)
static double now(void) {
    struct timespec t;
    if(clock_gettime(CLOCK_MONOTONIC,&t)) exit(2);
    return t.tv_sec+1e-9*t.tv_nsec;
}
int main(int argc,char **argv) {
    if(argc!=5 && argc!=6) { fprintf(stderr,"trial-file elements-per-dataset chunk-elements durable(0|1) [datasets]\n"); return 2; }
    size_t n=(size_t)strtoull(argv[2],0,10), chunk=(size_t)strtoull(argv[3],0,10);
    int durable=atoi(argv[4]);
    int datasets=argc==6 ? atoi(argv[5]) : 1;
    if(datasets<1 || datasets>100000 || n<1 || n>134217728/(size_t)datasets ||
       chunk>n || (durable!=0 && durable!=1)) return 2;
    double *in=malloc(n*sizeof *in), *out=malloc(n*(size_t)datasets*sizeof *out);
    if(!in || !out) return 2;
    for(size_t i=0;i<n;i++) in[i]=1.0+(i%1024)*0.001;
    hsize_t dims[1]={(hsize_t)n}, chunks[1]={(hsize_t)chunk};
    double t=now();
    hid_t f=H5Fcreate(argv[1],H5F_ACC_TRUNC,H5P_DEFAULT,H5P_DEFAULT); CHECK(f);
    hid_t s=H5Screate_simple(1,dims,0); CHECK(s);
    hid_t dcpl=H5Pcreate(H5P_DATASET_CREATE); CHECK(dcpl);
    if(chunk) CHECK(H5Pset_chunk(dcpl,1,chunks));
    for(int k=0;k<datasets;k++) {
        char name[64]; snprintf(name,sizeof name,"data_%06d",k);
        hid_t d=H5Dcreate2(f,name,H5T_IEEE_F64LE,s,H5P_DEFAULT,dcpl,H5P_DEFAULT); CHECK(d);
        CHECK(H5Dwrite(d,H5T_NATIVE_DOUBLE,H5S_ALL,H5S_ALL,H5P_DEFAULT,in));
        CHECK(H5Dclose(d));
    }
    CHECK(H5Pclose(dcpl)); CHECK(H5Sclose(s)); CHECK(H5Fclose(f));
    if(durable) {
        int fd=open(argv[1],O_RDWR);
        if(fd<0 || fsync(fd)<0) { perror("fsync"); return 1; }
        if(close(fd)<0) return 1;
    }
    double writing=now()-t;
    t=now();
    f=H5Fopen(argv[1],H5F_ACC_RDONLY,H5P_DEFAULT); CHECK(f);
    for(int k=0;k<datasets;k++) {
        char name[64]; snprintf(name,sizeof name,"data_%06d",k);
        hid_t d=H5Dopen2(f,name,H5P_DEFAULT); CHECK(d);
        CHECK(H5Dread(d,H5T_NATIVE_DOUBLE,H5S_ALL,H5S_ALL,H5P_DEFAULT,out+(size_t)k*n));
        CHECK(H5Dclose(d));
    }
    CHECK(H5Fclose(f));
    double reading=now()-t, error=0;
    for(size_t i=0;i<n*(size_t)datasets;i++) {
        double e=fabs(out[i]-in[i%n]);
        if(!isfinite(out[i])) return 1;
        if(e>error) error=e;
    }
    if(error>1e-12) { fprintf(stderr,"readback error %.17g\n",error); return 1; }
    printf("write_create_close,%.17g,%.17g\nread_open_close_warm,%.17g,%.17g\n",writing,error,reading,error);
    free(in); free(out);
    if(unlink(argv[1])<0) { perror("unlink trial file"); return 1; }
    return 0;
}
C
profile_flags full
read -r -a cargs <<< "$EXE_CFLAGS"
read -r -a largs <<< "$EXE_LDFLAGS"
"$CC" "${cargs[@]}" -I "$TRIAL_ROOT/install/hdf5/full/include" \
  "$TRIAL_ROOT/bench/hdf5_bench.c" -L "$TRIAL_ROOT/install/hdf5/full/lib" \
  -Wl,--enable-new-dtags -Wl,-rpath,"$TRIAL_ROOT/install/hdf5/full/lib" \
  -lhdf5 -lm "${largs[@]}" -o "$TRIAL_ROOT/bench/hdf5-fixed"
```

## 3. Measure on the actual filesystem (optional attribution)

For the primary comparison, finish the builds and continue to 11/08 first. These manual timings use library-only scope and are available for later package/control investigation.

Set the directory to a dedicated writable trial directory on the filesystem of interest. The example is 128 MiB of data; ensure adequate memory and disk space. Use a larger fixed data size if transfer phases are too short. Choose distinct case labels for different filesystems/cache/durability settings.

```bash
export IO_DIR=/absolute/path/to/test-filesystem/hdf5-hardening-trial
mkdir -p "$IO_DIR"
df -T "$IO_DIR" > "$TRIAL_ROOT/logs/hdf5-filesystem.txt"
export COMPARE=reference PAIRS=10 TRIAL_SCOPE=library
unset COMPARE_EXECUTABLE
taskset -c "$CPUSET" python3 "$TRIAL_ROOT/bench/paired.py" \
  hdf5 "$TRIAL_ROOT/bench/hdf5-fixed" contiguous-128MiB-buffered \
  "$IO_DIR/hdf5-trial.h5" 16777216 0 0
taskset -c "$CPUSET" python3 "$TRIAL_ROOT/bench/paired.py" \
  hdf5 "$TRIAL_ROOT/bench/hdf5-fixed" chunked-128MiB-buffered \
  "$IO_DIR/hdf5-trial.h5" 16777216 65536 0
taskset -c "$CPUSET" python3 "$TRIAL_ROOT/bench/paired.py" \
  hdf5 "$TRIAL_ROOT/bench/hdf5-fixed" contiguous-128MiB-fsync \
  "$IO_DIR/hdf5-trial.h5" 16777216 0 1
```

Add a CPU-visible I/O case using a recorded node-local or tmpfs directory with sufficient capacity and new labels. Keep the remote filesystem case too: storage latency can mask compiler costs. Do not drop system caches on a shared machine. ReFrame's `hdf5-metadata` case writes 1,000 datasets of 128 doubles each (1,000 KiB logical data). It measures many small creation/transfer/lookup calls, not metadata alone. Cold reads and the application's real access pattern remain additional workloads.

The supplied `h5perf_serial` tool can add small-transfer/metadata pressure. Inspect the installed version's `-h` output first and retain its full command/output. Its executable changes with each build, so that comparison includes both tool and library hardening; label it accordingly rather than combining it with fixed-caller results.

## 5. Binding, compression, executable, and MPI extensions

* **Serial C++/Fortran:** use a separate matrix/prefix name, enable `HDF5_BUILD_CPP_LIB` and `HDF5_BUILD_FORTRAN`, set `CMAKE_CXX_COMPILER`/`CMAKE_Fortran_COMPILER` to the new GNU drivers, and pass the matching `CXXFLAGS`/`FFLAGS` with empty language-specific release flags. Run their upstream tests. The C caller above does not measure binding overhead; use callers in those languages when that is the question.
* **Compression:** install one fixed compression provider, enable its HDF5 option, and repeat with the same filter/level. A compression-provider rebuild is a different experiment. Keep plugin loading disabled unless it is part of the declared workload.
* **PIE:** rebuild only this caller with `minus-pie` while keeping full HDF5 loaded. Compare whole-process runtime separately from I/O phase timing.
* **MPI:** build and qualify [Open MPI + UCX](00b-openmpi-ucx.md), then use [05 — Parallel workloads](05-parallel.md) for a fresh parallel matrix and collective/independent I/O caller. Keep ranks, placement, filesystem, and MPI-IO settings fixed. The serial driver above does not measure MPI-IO.
